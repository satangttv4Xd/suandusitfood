# SUAN DUSIT FOOD GUIDE

เว็บไซต์แนะนำร้านอาหารภายในและรอบมหาวิทยาลัยสวนดุสิต พร้อมระบบหลังบ้านให้ผู้ดูแล
เพิ่ม / แก้ไข / ลบข้อมูลร้าน เมนู รูปภาพ และหมวดหมู่ได้เองทั้งหมดโดยไม่ต้องแก้โค้ด

> โปรเจกต์เพื่อการศึกษา ไม่ใช่เว็บไซต์ทางการของมหาวิทยาลัยสวนดุสิต
> ข้อมูลร้านตัวอย่างที่มากับระบบเป็นข้อมูลสมมติสำหรับทดสอบ

---

## 1. ติดตั้งและรัน (Step by Step)

ต้องมี [Bun](https://bun.sh) 1.3 ขึ้นไป ตรวจสอบด้วย `bun --version`
(ถ้ายังไม่มี บน Windows เปิด PowerShell แล้วรัน `powershell -c "irm bun.sh/install.ps1 | iex"`)

```bash
# 1) เข้าโฟลเดอร์โปรเจกต์
cd suandusitfood

# 2) ติดตั้ง dependency
bun install

# 3) รันเว็บไซต์ (frontend + ข้อมูล ทำงานพร้อมกันในคำสั่งเดียว)
bun dev
```

เปิดเบราว์เซอร์ที่ **http://localhost:5173**
(ถ้าพอร์ต 5173 ถูกใช้อยู่ Vite จะเลื่อนไป 5174 เอง — ดูเลขพอร์ตจริงที่เทอร์มินัลบอก)

| คำสั่ง | ทำอะไร |
|---|---|
| `bun dev` | รันเว็บไซต์โหมดพัฒนา มี Hot Reload |
| `bun run build` | สร้างไฟล์สำหรับขึ้นเซิร์ฟเวอร์จริงลงโฟลเดอร์ `dist/` |
| `bun run preview` | ทดลองเปิดไฟล์ที่ build แล้ว |
| `bun run lint` | ตรวจคุณภาพโค้ดด้วย ESLint |

### เข้าหน้าผู้ดูแลระบบ

**พิมพ์ URL `/admin` เองเท่านั้น** — เช่น **http://localhost:5173/admin**

หน้าเว็บฝั่งผู้ใช้ไม่มีปุ่มหรือลิงก์ไปหน้าหลังบ้านเลยสักจุด (ทั้ง Navbar, เมนูมือถือ
และ Footer) คนทั่วไปที่เข้าเว็บจึงไม่เห็นทางเข้าระบบหลังบ้าน และมี `robots.txt`
กัน Search Engine ไม่ให้เก็บ `/admin` ลงผลค้นหาด้วย

| ชื่อผู้ใช้ | รหัสผ่าน |
|---|---|
| `admin` | `admin123` |

เปลี่ยนรหัสผ่านได้ทันทีที่เมนู **ตั้งค่าข้อมูล → เปลี่ยนรหัสผ่าน**
ออกจากหลังบ้านกลับหน้าเว็บได้จากปุ่ม “ดูเว็บไซต์” ในแถบข้าง

### ขึ้นเซิร์ฟเวอร์จริง

`bun run build` แล้วอัปโหลดทุกอย่างในโฟลเดอร์ `dist/` ขึ้นโฮสต์
เนื่องจากใช้ client-side routing ต้องตั้งให้เซิร์ฟเวอร์ส่งทุก path กลับไปที่ `index.html`
(Netlify / Vercel / GitHub Pages ตั้งเป็น SPA fallback; Apache ใช้ `.htaccess` กับ `FallbackResource /index.html`)

## 3. เทคโนโลยีที่ใช้

| ส่วน | เทคโนโลยี |
|---|---|
| Runtime / ตัวจัดการแพ็กเกจ | Bun 1.3 |
| Build tool | Vite 8 |
| UI | React 19 + TypeScript (เปิด React Compiler) |
| CSS | Tailwind CSS v4 |
| Routing | React Router 7 |
| ฐานข้อมูล | localStorage ของเบราว์เซอร์ (ผ่าน `src/lib/db.ts`) |
| แผนที่ | Google Maps Embed — ไม่ต้องใช้ API key |
| ฟอนต์ | Playfair Display SC + Noto Serif Thai (หัวข้อ), Karla + IBM Plex Sans Thai (เนื้อความ) |

### เรื่องฐานข้อมูล

ระบบนี้เก็บข้อมูลทั้งหมดไว้ใน **localStorage ของเบราว์เซอร์** ตามที่ตกลงกันไว้
จึงรันได้ทันทีโดยไม่ต้องติดตั้ง MySQL, XAMPP หรือเซิร์ฟเวอร์ใด ๆ

สิ่งที่ต้องรู้:

- ข้อมูลผูกกับ **เบราว์เซอร์และเครื่องที่ใช้** เปิดคนละเครื่องจะเห็นข้อมูลคนละชุด
- ล้าง Cache / Site data ของเบราว์เซอร์ = ข้อมูลหาย → **ควรกด “ดาวน์โหลดไฟล์สำรอง” ที่หน้าตั้งค่าเป็นระยะ**
- localStorage มีพื้นที่ราว 5 MB ระบบจึงย่อรูปที่อัปโหลดให้อัตโนมัติ (ด้านยาวสุด 1400 px, แปลงเป็น WebP)
  และแสดงแถบพื้นที่ที่ใช้ไปในหน้า Dashboard

โครงสร้างข้อมูลถูกออกแบบให้ตรงกับฐานข้อมูลเชิงสัมพันธ์จริงแบบหนึ่งต่อหนึ่ง
ดู `database/database.sql` — ถ้าอยากย้ายไปใช้ MySQL จริงในอนาคต
**แก้แค่ไฟล์ `src/lib/db.ts` ให้เรียก `fetch()` ไปที่ API แทน localStorage**
โดยไม่ต้องแตะโค้ดหน้าเว็บเลย

## 4. คู่มือผู้ดูแลระบบ

### เพิ่มร้านอาหารใหม่

1. เข้าสู่ระบบที่ `/admin`
2. เมนู **ร้านอาหาร → เพิ่มร้านใหม่**
3. กรอกข้อมูล — ช่องที่มี `*` เป็นช่องบังคับ:
   ชื่อร้าน, คำอธิบาย, หมวดหมู่, ราคาเริ่มต้น, คะแนนตั้งต้น, เวลาเปิด-ปิด, วันที่เปิด
4. อัปโหลดรูปหน้าปก และรูปเพิ่มเติมสำหรับแกลเลอรี (สูงสุด 8 รูป)
5. ใส่ Latitude / Longitude เพื่อให้แผนที่ปักหมุดตรงจุด
   (เปิด Google Maps → คลิกขวาที่ตำแหน่งร้าน → ตัวเลขชุดแรกคือ Latitude)
6. กด **บันทึกร้านใหม่** → ร้านขึ้นบนหน้าเว็บไซต์ทันที ไม่ต้องรีเฟรชหรือแก้โค้ด

### เกี่ยวกับรูปภาพ

- รองรับ **JPG, JPEG, PNG, WEBP** ขนาดไม่เกิน 8 MB ต่อไฟล์
- ลากไฟล์มาวางได้ หรือคลิกเพื่อเลือกจากเครื่อง
- เห็นตัวอย่างรูปก่อนบันทึกเสมอ และกด “เปลี่ยนรูป” หรือ “ลบรูป” ได้ตลอด
- รูปในแกลเลอรีสลับลำดับได้ด้วยปุ่มลูกศร
- ถ้ามีลิงก์รูปอยู่แล้ว กด “หรือใส่ลิงก์รูปภาพแทน” ได้ ไม่ต้องดาวน์โหลดมาก่อน

### สถานะร้าน

- **เปิดให้บริการ** — ระบบคำนวณ “เปิดอยู่ / ปิดแล้ว” จากเวลาและวันที่ตั้งไว้ รองรับร้านที่ปิดหลังเที่ยงคืน
- **ปิดชั่วคราว** — บังคับให้ขึ้นว่าปิดตลอดเวลา ใช้ตอนร้านปิดปรับปรุงหรือปิดยาว

### ข้อมูลตัวอย่าง

ร้านตัวอย่างทั้ง 5 ร้านเป็นข้อมูลปกติในระบบ **แก้ไขหรือลบได้ทั้งหมด**
ถ้าลบไปแล้วอยากได้กลับมา ไปที่ **ตั้งค่าข้อมูล → คืนค่าข้อมูลตัวอย่าง**
ถ้าจะเริ่มกรอกข้อมูลจริงตั้งแต่ต้น ใช้ **ล้างข้อมูลทั้งหมด** (บัญชีแอดมินไม่ถูกลบ)

## 5. ความปลอดภัย

สิ่งที่ระบบทำไว้:

| หัวข้อ | วิธีที่ใช้ |
|---|---|
| รหัสผ่าน | PBKDF2-SHA256 150,000 รอบ + salt สุ่มรายบัญชี ไม่เก็บรหัสผ่านจริง |
| เปรียบเทียบรหัสผ่าน | เทียบแบบ constant-time และแฮชหลอกเมื่อไม่พบชื่อผู้ใช้ กันการเดาจากเวลาตอบ |
| กันเดารหัสผ่าน | ผิดเกิน 8 ครั้ง ล็อก 10 นาที |
| เซสชัน | เก็บใน sessionStorage หมดอายุใน 8 ชั่วโมง ปิดแท็บแล้วหลุดเหมือน session ฝั่งเซิร์ฟเวอร์ |
| กันคนนอกเข้าหลังบ้าน | ทุกเส้นทางใต้ `/admin` ผ่านตัวตรวจ `RequireAuth` ถ้าไม่ได้ล็อกอินจะเด้งไป `/admin/login` และพากลับหน้าเดิมหลังล็อกอินสำเร็จ |
| ไม่เปิดเผยทางเข้า | หน้าเว็บฝั่งผู้ใช้ไม่มีลิงก์ไป `/admin` เลย ต้องพิมพ์ URL เอง และ `robots.txt` กัน Search Engine ไม่ให้เก็บลงผลค้นหา (เป็นการลดการถูกสังเกตเห็น ไม่ใช่การยืนยันตัวตน — ด่านจริงคือ `RequireAuth` กับรหัสผ่าน) |
| CSRF | ทุกฟอร์มในหลังบ้านแนบโทเคนประจำเซสชันและตรวจก่อนบันทึก |
| XSS | React escape ข้อความให้อยู่แล้ว และมี `safeUrl()` กรอง scheme ของลิงก์ (อนุญาตเฉพาะ http, https, mailto, tel) ปิดช่อง `javascript:` |
| SQL Injection | ไม่มี SQL ในระบบนี้ — query ตัวอย่างใน `database.sql` เขียนเป็น prepared statement ทั้งหมด |
| ตรวจไฟล์อัปโหลด | ตรวจ 3 ชั้น: ชนิดไฟล์ (JPG/JPEG/PNG/WEBP), ขนาด (ไม่เกิน 8 MB) และ **ถอดรหัสเป็นรูปจริงได้หรือไม่** — ไฟล์ `.exe` เปลี่ยนนามสกุลเป็น `.jpg` จะไม่ผ่าน จากนั้นวาดใหม่ผ่าน canvas ซึ่งตัด metadata ที่ฝังมาทิ้งทั้งหมด |

**ข้อจำกัดที่ต้องพูดตรง ๆ:** ระบบนี้ทำงานฝั่งเบราว์เซอร์ล้วน ๆ ไม่มีเซิร์ฟเวอร์
คนที่เปิด DevTools บนเครื่องนั้นย่อมอ่านและแก้ localStorage ได้โดยตรง
การล็อกอินจึงป้องกัน “คนทั่วไปกดเข้าหน้า Admin” ได้ แต่ไม่ได้ป้องกันผู้ใช้เครื่องนั้นเอง
ซึ่งเหมาะกับงานระดับโครงงาน หากนำไปใช้จริงกับข้อมูลสำคัญ
ต้องย้ายการตรวจสอบสิทธิ์ทั้งหมดไปไว้ฝั่งเซิร์ฟเวอร์ (ดูหัวข้อฐานข้อมูลด้านบน)

## 6. UI / UX

- **ไม่ hardcode ข้อมูลร้านในหน้าเว็บ** ทุกการ์ด ทุกตัวเลข ทุกหมวดหมู่ อ่านจากชั้นข้อมูลเดียวกัน
  แก้ในหลังบ้านแล้วหน้าเว็บอัปเดตทันทีโดยไม่ต้องรีเฟรช (รวมถึงข้ามแท็บที่เปิดค้างไว้)
- **Responsive จริง** ทดสอบทุกหน้า (ทั้งฝั่งผู้ใช้และหลังบ้าน) ที่ความกว้าง
  320 / 360 / 390 / 768 / 820 / 1024 / 1180 / 1440 px — ไม่มีหน้าไหนเลื่อนออกด้านข้างเลย

| ช่วงความกว้าง | อุปกรณ์ | สิ่งที่เปลี่ยน |
|---|---|---|
| < 640 px | มือถือ | เมนูแบบแฮมเบอร์เกอร์, การ์ด 1 คอลัมน์, ตารางหลังบ้านเปลี่ยนเป็นการ์ด, แถบหมวดหมู่เลื่อนแนวนอน |
| 640–767 px | มือถือแนวนอน / แท็บเล็ตเล็ก | การ์ด 2 คอลัมน์, กล่องข้อมูลร้านกับแผนที่วางคู่กัน |
| 768–1023 px | **iPad แนวตั้ง** | เมนูเต็มบนแถบนำทาง (ไม่ใช่แฮมเบอร์เกอร์แล้ว), แผนที่ย่อเป็น 16:9 ไม่สูงเกินจอ |
| 1024–1279 px | **iPad แนวนอน** | แถบข้างหลังบ้านแสดงถาวร, การ์ดสรุปหน้า Dashboard เรียง 4 ช่อง, หน้ารายการร้านมีแถบตัวกรองด้านซ้าย |
| ≥ 1280 px | Desktop | คอลเลจรูปในหน้าแรก, การ์ด 3 คอลัมน์, ฟอร์มเพิ่มร้านแบ่ง 2 คอลัมน์ |

ปุ่มและลิงก์ที่ต้องกดด้วยนิ้วมีความสูงอย่างน้อย ~36–44 px รวมถึงลิงก์ใน Footer
- ตัวกรองและคำค้นเก็บไว้ใน URL — ก๊อบลิงก์ส่งให้เพื่อนได้ตรงตามที่กรองไว้
- ค้นหาครอบคลุมทั้งชื่อร้าน คำอธิบาย ที่อยู่ หมวดหมู่ และ **ชื่อเมนู**
  (นักศึกษาค้น “กะเพรา” บ่อยกว่าค้นชื่อร้าน)
- ไอคอนเป็น SVG ทั้งหมด ไม่ใช้อิโมจิ, ปุ่มและการ์ดที่กดได้มี `cursor-pointer` และ hover ที่ไม่ทำให้เลย์เอาต์ขยับ
- รองรับคีย์บอร์ด: มีลิงก์ข้ามไปเนื้อหาหลัก, focus ring ชัดเจน, ปิดป๊อปอัปด้วย Esc
- เคารพ `prefers-reduced-motion` — ปิดแอนิเมชันให้ผู้ใช้ที่ตั้งค่าไว้

### โทนสี

ใช้ **สีฟ้าน้ำทะเล** ซึ่งเป็นสีประจำมหาวิทยาลัยสวนดุสิตเป็นสีหลัก และ **สีทอง**
จากวงรีด้านนอกของตรามหาวิทยาลัยเป็นสีรอง (ปุ่มรอง ดาวคะแนน ป้ายราคา)
ส่วนสีน้ำเงินเข้มอมเขียวที่ไล่มาจากฟ้าน้ำทะเลใช้เป็นสีโครงสร้าง — Navbar, Footer
และหน้าหลังบ้าน สีเทาทั้งหมดปรับให้อมฟ้าเล็กน้อยเพื่อไม่ให้หลุดโทน

ใช้เฉพาะ "สี" ตามอัตลักษณ์ ไม่ได้ลอกเลย์เอาต์หรือองค์ประกอบของเว็บไซต์มหาวิทยาลัย
และรูปอาหารซึ่งเป็นโทนอุ่นจะยิ่งเด่นขึ้นเมื่อวางบนพื้นเย็น

สีทั้งหมดนิยามเป็น token ไว้ที่เดียวใน [`src/index.css`](src/index.css)
(`--color-brand-*`, `--color-gold-*`, `--color-navy-*`) ถ้าต้องการปรับโทน
แก้ที่ไฟล์นี้ไฟล์เดียวแล้วเปลี่ยนทั้งเว็บ

พื้นสีเข้ม (Footer, กล่อง “งบไม่ถึงร้อย”, แถบข้างหน้า Admin, หน้า Login)
ใช้น้ำเงินอมเขียวที่ยัง **สด** อยู่ ไม่ใช่สีเกือบดำ เพราะพื้นที่หม่นเกินไปจะอ่านยาก
และการ์ดย่อยข้างในใช้พื้นเข้มกว่าพื้นหลัง (inset) แทนการทาขาวจาง ๆ ทับ
เพราะพื้นขาวจางจะดันพื้นหลังเข้าใกล้สีตัวอักษรทองจนคอนทราสต์ตก

ตรวจค่า contrast ตามเกณฑ์ WCAG AA แล้วทุกจุดหลัก:

| จุด | อัตราส่วน |
|---|---|
| ตัวอักษรเนื้อความบนพื้นหลัก | 7.8:1 |
| ข้อความรอง 14px | 5.1:1 |
| ปุ่มหลัก (ขาวบนฟ้าน้ำทะเล) | 5.2:1 |
| ปุ่มสีทอง | 7.5:1 |
| หัวข้อบนกล่องสีเข้ม | 6.2:1 |
| ชื่อร้าน / ราคาในการ์ดบนพื้นเข้ม | 8.7:1 / 6.6:1 |
| ข้อความใน Footer | 5.4–8.3:1 |

ปุ่มสีทองใช้ตัวอักษรสีน้ำเงินเข้มบนพื้นทอง เพราะตัวอักษรขาวบนทองได้แค่ 3.3:1 ซึ่งไม่ผ่านเกณฑ์
